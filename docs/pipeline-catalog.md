## Facts that change how agents must work
- SketchEngine = CodeSketch v2 (same framework, user-optimized and renamed). Version delta: renames (`CodeSketchDebug`->`SketchDebug`, `Utils*`->`Utility*`, `Haptic`->`Taptic`), `OptCollisionRegister<T>` -> non-generic with `owner is T`, `DataBlock.Instance` -> `INSTANCE`, autosave (2 s debounce, atomic write, background thread) vs save on pause/quit plus hand-written `DataBlockPreloader`.
- Singleton assets load by `Resources.Load("<Root>/<full type name>")`; Editor auto-creates a missing one, a build returns null.
- Collision: one dictionary keyed by collider instance ID gives O(1) owner lookup with no `GetComponent` and no allocation; static maps are never reset on domain reload/scene load; about 15 knife-tower files still use raw `OnTriggerEnter`.
- Pooling is the framework's `PoolPrefabGlobal` with `PoolPrefabConfig` assets and `Pool_Manager`; there is no LeanPool.
- Canvas: persistent `GameSingleton` prefab with two Overlay canvases (HUD sort 2506, popups 12506), CanvasScaler 1920x1080 Expand match 0, 100 ppu; popups are instantiated under the popup root, never separate canvases; no nested-canvas isolation; no banner-clearance code (200 px is only a layout convention).
- Popup anatomy: `Popup(CanvasGroup) > Root > Scale > Board > Btn_Close`, destroyed on close; scale starts 0.3, OutBack, 0.1/0.1 s (large 0.3/0.2); buttons carry `UIPressPrimeTween` (0.9 scale, 0.1 s) and `AudioButtonSfx`.
- Feel table (Roblox-clone controller): speed 4.5 m/s, gravity -30, jump 11 m/s (2.02 m), coyote and jump buffer 0.5 s, capsule r0.3/h1.7, FreeLook camera damping 0, FOV 40-50.
- Asset discipline (thunder-break-egg): meshes generated by Editor scripts into `.asset` (FBX only reference art); one material per family (map/decor, eggs, pickaxes), vertex colors baked linear, extra data in uv channels; characters keep ~136 OmniShade materials by user decision; measured 3767/149 -> 1/1 per segment, 93 batches in Play, not measured on device.

## Contradictions with current AGENTS.md or existing skills (to fix)
1. Pooling is named "PoolManager/LeanPool"; real standard is `PoolPrefabGlobal`/`Pool_Manager`/`Factory_Pool`.
2. Framework text treats CodeSketch and SketchEngine as separate; should be one framework with a version delta table.
3. "Mobile and PC Quality tiers": reference projects have ONE Quality level "Mobile"; tiering is runtime `DevicePolicy`/`Device.cs` (GPU+RAM). Their Mobile URP asset has HDR on, soft shadows, shadow distance 50, above the stated baseline.
4. 60 fps cap (vSync 0) missing from AGENTS.md.
5. "Prefer PrimeTween": reference projects use DOTween (48 files) and PrimeTween (39) side by side.
6. "OmniShade" is character-skin only; world uses URP Lit/SimpleLit plus 17 custom shaders, 3 of them (including AutoTiling) not SRP Batcher compatible.
7. Rule "reset static collections on SubsystemRegistration" is violated by the framework collision maps and `Teleporter`.
8. Rule "pair every StaticBus subscribe" is violated in knife-tower `AI.cs`.
9. `ui-style-rules` says icon <= ~50% of button; measured median 72% but mixes background layers: needs role split before editing.
10. AGENTS.md says single shared material goal; reality is one material per family.

## Proposed build order (waves)
1. **Foundation (changes every output):** `framework-version-map`, `boot-sequence-setup`, templates (`data-block`, `factory-singleton`, `mono-singleton`, `static-bus-events`, `state-machine`), `collision-registry`, pooling/config authoring, `device-tier-policy`, art rules (shader/material/vertex color/import), `canvas-structure`, anti-pattern ledger.
2. **UI engine:** miner tool (generalise `mine_ui.py`, `inset.py`, `deep.py`), design principles and tokens, button/text/icon-label anatomy, popup anatomy, states, list/grid, naming, localization, feedback/toasts/tabs, 21 screen patterns, idempotent builder, validator, screenshot QA at 3 ratios.
3. **Gameplay and economy recipes:** KCC controller, camera, platform kit, checkpoint, bots, nav tool, minigame registration and scaffold, daily/jackpot/gacha/restock, IAP and ads extensions, compliance checks.
4. **Orchestration:** GDD intake, orchestrator and subagents (designer, dev, UI, tester, balancer), hooks, auto-balance loop with stop criteria, local batch runner.
5. **Pilot** on one new clone from a GDD, measure time and misses, then fold feedback back.
