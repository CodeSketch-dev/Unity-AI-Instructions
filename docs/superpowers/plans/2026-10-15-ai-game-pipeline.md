# AI Game Production Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This file is the durable progress tracker: tick boxes as work lands and note the date. Session/account switches resume from the first unticked box (read `docs/agent-handoff.md` first).

**Goal:** One installable suite of skills, rules, hooks, subagents, commands and automation that turns a Roblox-clone GDD into a complete local Unity mobile game in about 1 day.

**Architecture:** Skills are the generic engine (progressive disclosure, ~1-2 line descriptions, detail in `references/`, executable checks in `scripts/`); an orchestrator skill + subagent roster reads a machine-readable GDD and builds a task graph; hooks enforce compile/wiring/protected-file gates; QA and auto-balance loops run with iteration caps; everything is packaged as a Claude Code plugin and still installable by the existing `sync.bat`. Evidence base is `docs/pipeline-catalog.md` and `docs/pipeline-catalog/01..22-*.md`.

**Tech Stack:** Markdown skills, Python 3 via `py` (scripts), C# Unity Editor tools (idempotent), Unity MCP (ivanmurzak), UniTask/PrimeTween/SketchEngine in target projects, Claude Code hooks/subagents/plugins, and local Unity batch build/QA automation.

**Spec:** `docs/superpowers/specs/2026-10-15-ai-game-pipeline-design.md`

## Global Constraints
- Chat Vietnamese; every file, skill, comment and note in English; terse.
- Skills only in `skills/` of this repo (installed copies are generated by `sync.bat`/plugin). Unity projects under `C:\Unity\GitProject\*` are read-only references; ask before writing anything there.
- Never commit/push/branch unless the user asks; commit steps below are "when asked".
- Skill file: `skills/<name>/SKILL.md` with frontmatter `name` equal to folder name and a 1-2 line `description` that says when to trigger; body < 500 lines, explains WHY; detail in `references/`, helpers in `scripts/`/`assets/`.
- Rules are principles + reason + soft defaults; each mined number cites its report (e.g. "report 07"). Hard rules only for compile, wiring, data loss, protected files.
- Detect framework version from `Packages/manifest.json` (`com.codesketch` vs `com.sketchengine`); never invent API of the other version.
- Parallel agents follow the AGENTS.md "never overwrite newer work" protocol; claim files before editing.
- Mark claims VERIFIED/INFERRED when they come from mining; flag what was not checked in the Editor.
- Never print or store secrets, keystores, keys.

## Review Focus
- A skill triggers on the wrong task or not at all (description collisions across 200+ skills): lint for duplicate trigger phrases and run trigger evals on the top 20.
- Mined numbers copied as hard rules and then breaking a game whose reference differs: every number must be a soft default with a "override when the reference shows otherwise" clause.
- Unity MCP/Editor unavailable: every Unity-touching skill states what is verified by files only and never claims Editor validation.
- Builder runs twice (retry): duplicate objects/assets; every generator must be idempotent and keyed by name/GUID.
- Context blow-up from reading huge scenes/prefabs/logs: scripts summarise; skills forbid raw dumps.
